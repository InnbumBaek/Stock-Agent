# 주가 모니터링

상장 포트폴리오사의 **회수(엑싯) 시점 판단**에 필요한 사실을 매일 자동으로 모아
단일 HTML 리포트로 만드는 도구입니다.

판단은 하지 않습니다. **측정값과, 그 측정값이 무엇을 셌는지, 어떤 가정 위에 서 있는지**만 냅니다.

---

## 무엇을 하는가

```bash
python ki_monitor.py daily
```

이 한 줄로 적재 → 매크로 수집 → 리포트 생성이 끝납니다.

리포트는 외부 리소스 0개인 **단일 HTML 파일**입니다. CDN을 부르지 않으므로
사내망이나 오프라인에서도 그대로 열립니다. 차트(SVG)도 라이브러리 없이 직접 그립니다.

### 리포트 구성 — 의사결정 순서

| § | 질문 |
|---|---|
| 1 | 무엇을 결정해야 하는가 — 회수계획 대비 진척 |
| 2 | 팔 수 있는가 — 처분 여건 |
| 3 | 어떻게 팔 것인가 — 실행 시뮬레이션 |
| 4 | 지금이 그 때인가 — 시장 환경 |
| 5 | 종목별 상세 |
| 6 | 밸류에이션 · 동종 비교 |
| 7 | 시장 배경 |
| 8 | 데이터 출처 · 한계 |

---

## 데이터 출처

크롤링하지 않습니다. 전부 공식 API입니다.

| 층 | 출처 | 인증 |
|---|---|---|
| 시세·지수·국고채·선물 | 한국거래소 KRX Open API | 헤더 `AUTH_KEY` |
| 공시·재무 | 금융감독원 DART Open API | 쿼리 `crtfc_key` |
| 해외 매크로 (선택) | FRED (세인트루이스 연준) | 쿼리 `api_key` |

자세한 이용 조건은 [`SOURCES.md`](SOURCES.md) 를 보십시오.
제3자 저작물(Nasdaq·ICE·Cboe 계열)은 기본값에서 제외되어 있습니다.

---

## 핵심 계산

- **처분 소요일수** — 시가총액 대비 물량을 장내에서 파는 데 걸리는 영업일수.
  평균 거래량 기준과 **중앙값 기준**을 나란히 냅니다. 거래대금이 상위 며칠에
  몰리는 종목은 평균값이 낙관적이기 때문입니다.
- **실행 시뮬레이션** — 매도 규칙 4종(즉시·균등·유동성비례·유동성상위일)을
  과거 구간마다 반복해 실현단가를 비교합니다. 가격 충격은 제곱근 모형을 가정합니다.
- **시장 국면** — 수준이 아니라 **분위**로 봅니다. "국고채 3.8%"는 맥락 없이
  높다 낮다 할 수 없지만 "관측기간 91분위"는 말할 수 있습니다.
- **매물대** — 가격대별 거래대금 분포.
- **수정주가** — 무상증자와 전환사채 희석을 구분합니다. 주가 실측이 주식수
  비율을 뒷받침할 때만 보정하고, 아니면 '확인 필요'로 남깁니다.

---

## 설계 원칙

**1. 예외가 안 난다고 맞는 게 아닙니다.**
금융 데이터 코드는 조용히 틀립니다. 컬럼이 뒤바뀌어도, 단위가 천원이어도 계산은 돌아갑니다.
그래서 교차검산·항등식·방향성 테스트를 둡니다.

```bash
python ki_monitor.py selftest    # 104개
```

**2. 모른다는 것을 아는 게 낫습니다.**
F-Score 항목 하나가 비면 0으로 채우지 않고 `None` 을 냅니다.
표본이 부족하면 계산을 거부합니다. 추적 불가 항목은 지우지 않고 '확인 불가'로 표시합니다.

**3. 가정을 드러냅니다.**
처분 소요일수는 참여율 가정, 가격 충격은 제곱근 모형 가정입니다.
숫자만 내면 가정이 숨습니다. 리포트에 가정을 적고 민감도를 함께 냅니다.

**4. 판단은 사람이 합니다.**
이 도구는 등급·점수·권고를 내지 않습니다. 재기만 합니다.

여기서 "사람이 한다"는 것은 *파이프라인이 판단하면 안 된다*는 뜻이 아니라,
**자동화가 만든 산출물을 놓고 최종 결정은 회의에서 사람이 한다**는 뜻입니다.
그래서 같은 저장소의 에이전트 데스크가 내린 판정을 리포트에 **별도의 절로**
실을 수 있습니다 ([`--with-agents`](#에이전트-판정-싣기----with-agents)).
측정값과 같은 표에 섞지 않는 것이 이 원칙의 실제 내용입니다.

## 시작하기

```bash
# 1) 키 설정
cp .env.example .env        # 그리고 값을 채웁니다
python ki_monitor.py check-auth

# 2) 감시 대상 지정
cp watchlist.sample.csv watchlist.csv
cp exit_plan.sample.csv exit_plan.csv

# 3) 과거 데이터 적재 (1년치, 약 30분)
python ki_monitor.py ingest --from 20250101 --universe KOSDAQ
python ki_monitor.py fundamentals --market KOSDAQ

# 4) 리포트
python ki_monitor.py report
```

### 필요 패키지

```
pandas numpy scipy requests lxml
```

`weasyprint` 가 있으면 PDF도 만듭니다. 없으면 HTML만 생성합니다.

## 다른 도구에 넘기기 — `facts`

같은 저장소의 [`trading-floor/`](../trading-floor/) (AI 에이전트 데스크) 가 이 원장의
실측값을 읽어 갈 수 있게, 리포트와 같은 재료를 JSON 으로도 냅니다.

```bash
python ki_monitor.py facts --codes 000660,005930 --indent 2
```

새로 계산하는 지표는 하나도 없습니다. HTML 리포트와 같은 함수에서 같은 값이 나옵니다.
표현만 다릅니다.

넘길 때도 원칙은 같습니다.

- **판단을 넘기지 않습니다.** 등급·점수·권고를 만들지 않습니다. 받는 쪽이 판정을
  내리더라도 그 재료는 측정값이어야지, 이 파일이 미리 내린 결론이어서는 안 됩니다.
- **모르면 `null` 입니다.** 0 으로 채우지 않습니다. 받는 쪽이 '측정 못 함'과
  '0으로 측정됨'을 구분할 수 있어야 합니다.
- **가정을 함께 넘깁니다.** `assumptions` 에 처분 참여율·보호예수 추정·업종 표본
  기준이 그대로 들어갑니다. 숫자만 넘기면 받는 쪽에서 가정이 사라집니다.
- **단위를 함께 넘깁니다.** `units` 에 측정값마다 무엇을 센 것인지 적습니다.
  금융 데이터는 단위가 틀려도 계산이 돌아가기 때문입니다.
- **네트워크를 쓰지 않습니다.** 원장에 있는 것만 냅니다. 원장이 오래됐으면
  `stale_days` 로 알릴 뿐, 몰래 새로 받아오지 않습니다.
  공시까지 필요하면 `--with-disclosures` 를 명시적으로 주십시오.

`stdout` 은 JSON 만 나갑니다. 진단 메시지는 전부 `stderr` 로 갑니다.
스키마와 사용처는 [`../docs/integration.md`](../docs/integration.md) 를 보십시오.

### 막힌 망에서의 일봉 — `candles`

데스크는 무료 공개 API(야후)로 캔들을 받는데, 사내망·폐쇄망에서는 그게 막혀
분석 자체가 섭니다. 그럴 때 **이미 한국거래소 공식 API 로 받아 둔 일별 시세**를
내보냅니다.

```bash
python ki_monitor.py candles --code 000660 --days 200
```

기본은 수정주가입니다(`--raw` 로 원주가). OHLC 가 하나라도 빈 봉은 버립니다 —
0 으로 채우면 지표가 조용히 틀어집니다. 기준일과 경과일수가 함께 나가므로 받는
쪽이 이것을 실시간 시세로 오해하지 않습니다.

## 에이전트 판정 싣기 — `--with-agents`

같은 저장소의 [`trading-floor/`](../trading-floor/) 에이전트들이 분석·토론해 내린
판정을 리포트에 한 절로 싣습니다.

```bash
# 1) 데스크에서 분석하고 브리핑을 만듭니다 (수 분/종목)
cd ../trading-floor
node server/export-brief.js --run --symbols SKHYNIX,SAMSUNG

# 2) 리포트를 만듭니다
cd ../stock-monitor
python ki_monitor.py report --with-agents
```

목차가 `1~4 → 5 에이전트 분석 → 6~9` 로 바뀌고, 판정·확신도·진입/손절/목표·
리스크 게이트 결과·근거가 실립니다. 애널리스트 리포트와 토론 로그는 **요약하지 않고
전문 그대로** 접이식으로 들어갑니다 — 회의에서 결론만 보고 넘어가지 않도록.

이 절이 지키는 것:

- **측정값과 섞지 않습니다.** 별도의 절이고, 머리에 "AI 에이전트의 판정입니다 —
  위 절들의 측정값과 성격이 다릅니다" 배너가 붙습니다.
- **언제 분석한 것인지 밝힙니다.** 분석 시각, 새로 돌린 것인지 저장된 것을 모은
  것인지, 참고한 원장 기준일까지 적습니다. 데모(목업) 런이면 그 사실도 적습니다.
- **강등을 숨기지 않습니다.** 리스크 게이트가 판정을 강등했으면 사유와 함께 싣습니다.
- **없으면 없다고 적습니다.** 브리핑이 없어도 리포트 생성은 멈추지 않습니다.

`--with-agents` 를 주지 않으면 리포트는 **통합 이전과 바이트 단위로 동일합니다.**

## 저장소에 포함되지 않는 것

아래는 `.gitignore` 로 제외됩니다.

- `.env` — API 키
- `watchlist.csv`, `exit_plan.csv`, `positions.csv` — 실제 감시 대상 (대외비)
- `ki.sqlite` — 원장 (API로 재생성 가능)
- `out/` — 생성된 리포트

**생성되는 리포트는 대외비 문서입니다.** 상단에 배포 통제 배너가 찍히며,
외부 공유 전에 사내 승인이 필요합니다.
